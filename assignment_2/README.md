# Практическое задание № 2. Клинические инструменты через MCP

Самостоятельный модуль проекта PIMIIM Александра Почтарёва. В [задании № 1](../README.md) агенты искали медицинские публикации через HTTP API. Здесь тот же сценарий поиска литературы доступен через внешний MCP-сервер, а в приложении появляются локальные детерминированные калькуляторы. Все три источника обслуживает один Streamlit-хост.

## Запуск

Из корня репозитория с Python 3.11 или новее и активированным виртуальным окружением выполните одну команду в Bash или PowerShell 7+.

```bash
python -m pip install -e ./assignment_2 && python -m clinical_mcp.launch
```

Откройте [Streamlit](http://127.0.0.1:8502). Запуск поднимает отдельный процесс Uvicorn на `127.0.0.1:8000`. Ключ API и LLM не требуются. Для PubMed нужен доступ в Интернет. Порты можно поменять аргументами `--sse-port` и `--web-port`. Остановка `Ctrl+C` закрывает оба процесса.

| Источник | Транспорт | Инструменты |
|---|---|---|
| Локальный stdio | Дочерний процесс `python -m clinical_mcp.server` | BMI, BSA, GCS и `list_calculators` |
| Локальный сетевой | `GET /sse`, затем `POST /messages/?session_id=…` | BMI, BSA, GCS, MAP, eGFR CKD-EPI 2021 и `list_calculators` |
| Внешний PubMed | Streamable HTTP, `https://pubmed.caseyjhand.com/mcp` | `pubmed_search_articles` из [Glama](https://glama.ai/mcp/connectors/io.github.cyanheads/pubmed-mcp-server) |

## Демонстрация на защите

1. Выберите **Локальный · stdio** → **Индекс массы тела · BMI** → **Подставить учебный пример** → **Вызвать инструмент**. Для 72 кг и 175 см ожидается ИМТ ≈ 23,51 кг/м².
2. Выберите **Локальный · SSE** → **Кардиология** → **MAP**. Включите учебный пример. При 120/80 ожидается ≈ 93,33 мм рт. ст. Затем поменяйте САД на 70. Сервер вернёт предупреждение с объяснением.
3. Выберите **Внешний · PubMed**, включите учебный пример и нажмите **Найти публикации**. Поиск `hypertension systematic review[pt]` показывает количество совпадений и краткие записи, доступные в ответе.
4. Внизу разверните **Инспектор JSON-RPC**. Покажите `initialize`, `notifications/initialized`, `tools/list` и пару `tools/call` с общим `id` в пределах сессии. Инспектор записывает реальные декодированные сообщения на границе MCP-клиента и транспорта. Каталог и вызов открывают отдельные сессии, поэтому идентификаторы могут повторяться. При попадании в кэш видны пакеты исходного обращения.

## Архитектура

Streamlit строит форму из `inputSchema`, полученной по `tools/list`, и отправляет значения по `tools/call`. Поиск внутри списка работает по русским названиям и латинским аббревиатурам. Категории группируют шкалы по специализации. Pydantic описывает строгие типы, а серверные функции проверяют диапазоны и связи между величинами. Для ошибок типа SDK отдаёт структурированный ответ с `isError: true`. Вне допустимого диапазона сервер возвращает `warning` без расчётного значения. Указанные границы относятся к поддерживаемому диапазону учебной формы.

Санитизатор приводит строки к числам и логическим значениям, пропускает пустые необязательные поля и подставляет синтетические данные только в явно выбранном учебном режиме. Указанные пользователем значения проходят на сервер без физиологической коррекции. Калькуляторы исполняются на сервере, через официальный MCP Python SDK 2.x. Сетевой клиент повторяет временно неуспешные обращения к SSE до трёх раз с задержками 0,25 и 0,75 секунды. Для PubMed действует общий таймаут в 12 секунд, каталог кэшируется на 5 минут, успешные поиски на 10 минут. Параметры поискового запроса отправляются внешнему провайдеру. Для проверки используйте только общие темы и синтетические данные.

## Контрольные вопросы

1. **MCP и REST / OpenAPI.** MCP задаёт общий жизненный цикл и операции обнаружения, описания и вызова инструментов. Сервер может совмещать инструменты, ресурсы и шаблоны подсказок. REST описывает взаимодействие через HTTP и ресурсы. OpenAPI позволяет описать контракт такого HTTP API.
2. **stdout при stdio.** Клиент воспринимает строки протокольного потока как JSON-RPC. Диагностические сообщения направляются в stderr. SDK 2.x дополнительно выделяет для протокола отдельные дескрипторы.
3. **`initialize` и `tools/call`.** Запрос содержит `jsonrpc`, `id`, `method` и `params`. У `initialize` в параметрах есть `protocolVersion`, `capabilities` и `clientInfo`. У `tools/call` есть `name` и `arguments`. Сервер отвечает с тем же `id` и полем `result` или `error`. Уведомление `notifications/initialized` передаётся без `id`.
4. **SSE и масштабирование.** Один сетевой сервис принимает несколько независимых сессий. Это позволяет нескольким хостам переиспользовать один сервер. Для многопользовательского развёртывания нужно учитывать HTTP-таймауты, аутентификацию и маршрутизацию запросов к процессу, который ведёт сессию. Здесь SSE доступен только на loopback.
5. **Автоматический перенос данных из истории болезни.** Сохранять происхождение каждого значения, проверять единицы, тип и диапазон, показывать пользователю сводку для подтверждения и вычислять формулу в детерминированном инструменте. При отсутствующем измерении в обычном режиме расчёт останавливается.
